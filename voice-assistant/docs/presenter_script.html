02
Introduction
1 min
India has 22 official languages and over 19,500 dialects. Yet today's voice assistants primarily serve English and Hindi speakers. That leaves 780 million Indians unable to use voice tech in their own language. Three core problems:
  1. Digital divide — 90% of India's internet users prefer local languages but services are English-first.
  2. Privacy — every voice query to Alexa or Google is sent to a remote server.
  3. Connectivity — 65% of rural India has unreliable internet.
Our project addresses all three — a fully offline, privacy-preserving voice assistant supporting Malayalam and 10 other Indian languages.
03
Objectives
1 min
Main objective: Design and develop a hyper-localized multilingual voice assistant with edge-computing capabilities and agentic AI workflows. Five specific objectives:
  1. Multilingual ASR — 85%+ accuracy for Malayalam. We achieved 97% with Pingala V1.
  2. Bidirectional translation — ML↔EN with 90%+ accuracy via IndicTrans2.
  3. Agentic AI — LangGraph routes queries to specialized agents.
  4. Edge readiness — under 3 seconds end-to-end latency.
  5. Privacy-preserving — all processing local, no data leaves the device.
04
Literature Review
1.5 min
We studied six existing systems: Google Assistant & Alexa — cloud-only, Hindi only, no Malayalam, privacy concerns. Rasa — local NLU but no ASR, TTS, or Indian language models. IndicTrans2 — great translation (22 languages) but no voice pipeline or agents. Whisper — 99 languages but lower accuracy for low-resource languages. Bhashini — government cloud APIs, no offline/edge support. Research gap: No system combines multilingual Indic ASR + local LLM + agentic workflows + edge deployment. That's what we built.
05
Proposed System
1 min
An end-to-end voice AI pipeline running entirely on-device. Key features: fully offline, 11 Indian languages, LangGraph agents, real-time dashboard. Advantages: zero cloud dependency, no API fees, local inference (<3s latency), extensible architecture. Core components: Pingala V1 (2.94% WER), IndicTrans2-Dist (211M params), Qwen3 via llama.cpp, MMS-TTS, LangGraph with 4 agents.
06
System Architecture
1 min
Three-layer architecture: Input layer — voice audio in any supported language. Processing layer — ASR → Translation (ML→EN) → Intent Detection → LangGraph Agent → LLM → Translation (EN→ML). Output layer — MMS-TTS converts text to speech audio. Agent system: LangGraph orchestrator routes to Info Agent, Task Agent, Chat Agent, and Smart Home Agent.

Prepared Q&A

Why not just use Google Assistant or Alexa?
They don't support Malayalam, require constant internet, send voice data to cloud servers, and charge API fees. Ours is fully offline, private, and free.
Why Pingala V1 over Whisper?
2.94% WER vs ~5.8% for Whisper on Indian languages. Designed specifically for Indic speech, runs efficiently on CPU.
Why Qwen3 and not GPT or Llama?
Best performance-to-size ratio. 0.6B–4B fits edge constraints. llama.cpp enables GGUF quantized inference on CPU. Zero API cost.
How do you handle untested languages?
IndicTrans2 supports all 22 scheduled Indian languages. We validated 11. Architecture is language-agnostic — no code changes needed.
What's the difference between the agents?
Info Agent = Q&A. Task Agent = to-dos/reminders. Chat Agent = conversation. Smart Home Agent = IoT control. LangGraph routes automatically by intent.
Why Docker instead of Raspberry Pi?
Budget. Docker with 2 CPUs, 4GB RAM limits accurately simulates Pi 5. Code and models are identical — only hardware differs. Deployment is straightforward when a Pi is available.
What about real-time performance?
~1.5s end-to-end: ASR 480ms, translation 250ms, LLM 340ms, TTS 380ms. Caching reduces repeats to <200ms.
How is this different from Bhashini?
Bhashini is a cloud API gateway — requires internet, no LLM, no agents. We run completely offline with intelligent task routing.
